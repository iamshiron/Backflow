# Shiron.Backflow.Ext.PostgreSql

Standalone .NET 10 PostgreSQL metadata adapter implementing Backflow's `ICache`.
Cache rows are evictable snapshots, not application entities or execution history.
Binary data stays in independent filesystem/S3/RustFS blob storage.

```csharp
// Deployment: use a dedicated DDL-capable data source once.
await PostgreSqlCacheProvisioner.ProvisionAsync(ownerDataSource, "backflow_cache", ct);

// Startup: dataSource is a caller-owned, restricted pooled NpgsqlDataSource.
await using var cache = new PostgreSqlCache(dataSource, new PostgreSqlCacheOptions {
    Scope = "node-results-v1",
    MaximumEntries = 1024,
    MaximumTotalBytes = 64 * 1024 * 1024,
    MaximumEntryBytes = 1024 * 1024,
    MaximumAge = TimeSpan.FromDays(7)
});
await cache.InitializeAsync(ct);
ICache metadataCache = cache;
```

The adapter provides atomic upsert/expiration/eviction, namespace policy verification,
bounded emission/reads, SHA-256 integrity, trusted-type deserialization and conditional
corrupt-row invalidation. Set commits immediately; no flush is required. Concrete
operations accept cancellation; unchanged ICache calls retain configured deadlines.

Custom persisted DTOs need explicit `AllowedTypes` on reopening. Share the initialized
cache across executions with separate immutable-option contexts. Caller-owned data
sources and blobs are not disposed or deleted by this adapter. Schedule `PruneAsync`
for idle scopes and configure PostgreSQL autovacuum and deployment disk quotas.

See [provisioning, permissions, resource limits and real PostgreSQL validation](https://github.com/iamshiron/Backflow/blob/dev/docs/cache-postgresql.md).
