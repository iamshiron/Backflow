# PostgreSQL metadata cache

`Shiron.Backflow.Ext.PostgreSql` is a standalone .NET 10, AGPL-3.0-only adapter
implementing existing `ICache`. It depends on Backflow and Npgsql, not an application
database model, ASP.NET Core or a particular blob store. Its data is **evictable cache
state**, never authoritative execution history, a job queue or application entities.

## Provision, initialize, register

Reference `src/Backflow.Ext.PostgreSql/Shiron.Backflow.Ext.PostgreSql.csproj` or its
NuGet package. It inherits enabled GitVersion and AGPL package metadata. Provision
once in a deployment/migration process using a dedicated DDL-capable connection:

```csharp
using Npgsql;
using Shiron.Backflow.Ext.PostgreSql;

await using var admin = NpgsqlDataSource.Create(adminConnectionString);
await PostgreSqlCacheProvisioner.ProvisionAsync(admin, "backflow_cache", cancellationToken);
```

Application startup uses a separate caller-owned pooled data source:

```csharp
using Shiron.Backflow.Caching;

await using var database = NpgsqlDataSource.Create(applicationConnectionString);
await using var cache = new PostgreSqlCache(database, new PostgreSqlCacheOptions {
    Schema = "backflow_cache",
    Scope = "node-results-v1",
    MaximumEntries = 1024,
    MaximumTotalBytes = 64 * 1024 * 1024,
    MaximumEntryBytes = 1024 * 1024,
    MaximumAge = TimeSpan.FromDays(7),
    MaximumConcurrentOperations = 8,
    OperationTimeout = TimeSpan.FromSeconds(30),
    AllowedTypes = [typeof(MyResult)]
});
await cache.InitializeAsync(cancellationToken);

ICache metadataCache = cache;
var executor = new PipelineExecutor(pipeline, metadataCache, blobResolver: blobResolver);
```

Connection strings, `MyResult`, pipeline and blob resolver belong to the consumer.
Supply credentials through secret configuration. Initialize before registering the
ready instance as a singleton `ICache` in your host's container; retain its explicit
lifetime until executions finish. No DI dependency, host-specific registration API,
constructor I/O or hidden DDL is required. Dispose cancels adapter operations, never
disposes the caller's data source or independent blob storage. Configure finite
data-source connection timeouts and pool limits as well.

Pass an optional `CacheTypeAdapterRegistry` as the third constructor argument.
Configure converters once before use; callbacks/getters must be thread-safe. Policy
is an immutable record and allowed types are snapshotted.

### Public contracts

* `PostgreSqlCacheProvisioner.ProvisionAsync(dataSource, schema, ct)` performs DDL.
* `PostgreSqlCache.InitializeAsync(ct)` creates/verifies one namespace using DML.
* Concrete `TryGetAsync(key, ct)`, `SetAsync(key, entry, ct)`, `RemoveAsync(key, ct)`,
  `ClearAsync(ct)` and `PruneAsync(ct)` accept cancellation.
* Existing `ICache` methods remain unchanged, explicitly implemented, with the same
  configured timeout and disposal cancellation even without caller tokens.
* Core `CacheEntrySerializer`, `CacheEntrySerializerOptions`, `SerializedCacheEntry`
  provide the shared bounded snapshot/type-allowlist contract used by both JSON and
  PostgreSQL metadata backends.

Unlike buffered `JsonFileCache`, PostgreSQL Set commits before returning; no flush is
needed. A disconnected commit can have an ambiguous result; retrying the same
deterministic key is safe. There is no transaction spanning node execution, metadata
and external blobs.

## Schema and migration ownership

Provisioning transactionally creates a dedicated schema:

| Table | Typed purpose |
|---|---|
| `schema_version` | Single revision marker, initially version 1. |
| `cache_scopes` | Namespace key plus entry-count, payload-byte, per-entry and lifetime policy. |
| `cache_entries` | Namespace/hash primary key, UUID revision, bounded snapshot bytes, SHA-256, creation/expiry timestamps, exact original ticks and generated byte count. |

Indexes support scope expiration and newest-first eviction. A database constraint
caps payloads at 16 MiB; configuration can only lower it. UTF-8 JSON is stored as
`bytea`, preserving exact checksum bytes rather than JSONB normalization. This is one
purpose-specific cache snapshot, not an EAV property bag or application entity model.
Application data/history belongs in its own properly modeled tables.

Schema names must be lowercase ASCII SQL identifiers. All namespace/key/value data
uses typed parameters. Use an application-owned schema and restricted database role;
never point the provisioner at foreign tables. Scopes are deployment-controlled
namespaces, not tenant authorization. Cache payload access needs the same protection
as original inputs/outputs; checksums are corruption detection, not authentication
against a database writer who can recompute them.

After provisioning, runtime needs schema USAGE, SELECT on `schema_version`,
SELECT/INSERT/UPDATE on `cache_scopes` (row locks require UPDATE privilege), and
SELECT/INSERT/UPDATE/DELETE on `cache_entries`. Runtime does not need DDL privileges.
The provisioner grants nothing to PUBLIC and does not manage application roles.

Provisioning is idempotent, protected by a transaction-level advisory lock. Unknown
schema versions fail closed: no implicit destructive upgrade/downgrade. Version 1 is
the initial migration; future structural changes require explicit transactional
migrations and revision updates, a compatible library, or a fresh disposable schema.
Every writer of one scope must match its persisted capacity/lifetime policy. To
change policy, deploy a new scope or stop writers, clear entries, explicitly update
policy and restart matching clients. Emptying entries does not reset policy.

## Transactions, lifetime and corruption

Writers serialize on their scope's PostgreSQL row lock. Upsert, expired-row pruning
and count/byte eviction commit together; failure rolls all changes back. Independent
scopes proceed independently. This intentionally favors predictable bounded capacity
over maximum write throughput within one scope. Readers use READ COMMITTED; newest
committed writer wins for a key. No process-local pending state survives restart.

Server time is sampled after scope lock acquisition. Already-expired/future-created
snapshots are not admitted. Lifetime starts at original creation, not last access;
clients should have synchronized UTC clocks. PostgreSQL expiry has microsecond
precision; separate original ticks preserve exact .NET snapshot identity. Capacity
retains the newest prefix by original UTC ticks and ordinal hash tie-breaking.

Cleanup runs on writes, requested expired/corrupt reads and explicit `PruneAsync`.
Schedule pruning at a host-controlled interval for idle scopes; no background thread
is started. Limits count live payloads, not PostgreSQL page/index/MVCC overhead.
Configure autovacuum, disk quotas and controlled namespace creation: these limits do
not bound physical database files or an unlimited number of scopes.

Reads use server-side CASE to avoid transferring oversized/expired payloads. UTF-8,
checksum, creation time, complete key and trusted types are verified before hits.
Corrupt, expired, incompatible, oversized and unknown-type rows become misses and are
deleted only if their observed UUID revision still matches. Stale invalidation cannot
delete a concurrent replacement. Database/permission failures propagate, never fake
a cache miss. Choose outage retry/fallback behavior explicitly in the host.

Persisted type names never pass through `Type.GetType` or assembly loading. Primitive
BCL scalars/arrays and Backflow blob cache contracts are built in. Trusted runtime
types observed on successful serialization work in that instance; reopening custom
DTOs requires `AllowedTypes`. There is no incorrectly typed JSON fallback.

## Actual options and separate blobs

Default keys hash actual immutable `ArrayPipelineContext` options through
`ICacheIdentityProvider`, alongside node/version/typed input identity. Complete keys
are verified, not only hashes. Do not substitute mutable globals or hand-maintained
identity strings. Declare additional semantic dependencies through the existing
identity provider/selector. Database connection/capacity policy does not change node
semantics and is not added to execution identity.

Store large binary outputs in independent filesystem, S3 or RustFS `IBlobStorage`.
PostgreSQL stores typed blob-reference contracts, not those bytes. Cache expiration,
clear and remove never delete blobs with potentially independent owners. Existing
executor/blob APIs retain integrity validation and ownership/garbage collection.
See [filesystem cache](cache.md) and [S3/RustFS](blob-storage-s3.md).

## Resource boundaries and validation

Serialization streams to the shared bounded destination, without an unbounded port
DOM or payload string. Effective limit is `min(MaximumEntryBytes, MaximumTotalBytes)`;
rejection writes nothing to PostgreSQL. Writer scratch reservations are capped at
six times that limit plus 4096 bytes. Default strings/raw JSON guard token expansion.
Caller values, arbitrary custom converter/getter allocations and serializer type
metadata cannot be sandboxed. JSON, UTF-8 and hashing necessarily allocate.

`MaximumConcurrentOperations` bounds active working buffers per adapter. Operation
timeout covers queueing, connection acquisition, lock waits and cooperative
serialization; cancellation/disposal aborts database operations and transactions.
It cannot preempt arbitrary user code, and Npgsql/network cancellation grace may
extend observed latency. No automatic retries conceal ambiguous commits.

Unit tests cover type safety, immutable snapshots, conditional invalidation, bounded
incremental output, existing ICache calls, initialization, queue/timeout cancellation
and disposal. All existing JSON-cache regressions exercise the extracted serializer.
Opt-in Testcontainers tests use isolated PostgreSQL 18 and a schema per case to test
actual MVCC/DDL/row locks/rollback, aggregate capacity, cancellation, version/policy
protection, bounded reads, stale revisions, and actual immutable executor options
across a fresh connection pool. Those semantics cannot be established by doubles.

```bash
BACKFLOW_POSTGRES_TESTS=1 dotnet test tests/Backflow.Tests.Ext.PostgreSql --configuration Release
```

For rootless Podman set `DOCKER_HOST` to its Docker-compatible socket. If required,
`TESTCONTAINERS_RYUK_DISABLED=true` disables its reaper; normal fixture disposal still
removes the test container. Tests skip without the opt-in flag. Development validation
used a real isolated Podman-backed PostgreSQL container, not an application database.
Production roles, HA/failover and network partitions require operator validation.
No inference or proprietary generation APIs are involved.
